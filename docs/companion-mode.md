# 陪伴模式指南 — 对话中自然维护记忆

> **Future layer exploration**  
> 本文描述的是未来 Companion Layer 的产品策略探索，不代表 CodeMemory v1 Core 的默认行为。  
> 当前正式产品定义见 `docs/prd.md`，正式架构见 `docs/architecture.md`。

> 与 `agent-memory-guide.md` 互补。后者面向结构化决策（投资、项目管理），本文面向拟人化日常陪伴。

---

## 一、核心差异

| | 决策模式 | 陪伴模式 |
|---|---|---|
| 记忆内容 | 事实、约束、判断、持仓 | 习惯、感受、人物、价值观、日常事件 |
| 创建时机 | 做出决策后显式记录 | 对话中自然流露时捕捉 |
| 信息密度 | 高（每条记忆都有推理链） | 低（一个感觉、一句话也可以） |
| intensity | 基于决策重要性和约束强度 | 基于提及频率 + 情感强度 |
| imports | 显式的因果/依赖关系 | 松散的主题/情感关联 |
| recall 目的 | 避免重复错误 | 制造"我记得"的亲密感 |

**关键：陪伴模式下的记忆门槛更低。** 决策模式下"我今天有点累"不会被记录，陪伴模式下会——因为它影响对话的语气和回应的分寸。

## 二、何时创建记忆

### 立刻创建

```
用户说"我喜欢/不喜欢/从不/永远..."          
  → user/preferences/

用户描述了一次具体的经历或事件                
  → user/moments/       （如果有情绪色彩→ user/feelings/）

用户提到一个重要的人（名字+关系+细节）         
  → user/people/

用户表达了明确的情绪（开心/难过/焦虑/兴奋/空虚）
  → user/feelings/

用户表达了一种信念、价值观、人生哲学             
  → user/beliefs/

用户说"记住这个" / "别忘了" / "帮我记一下"      
  → 无条件创建，目录按内容判断
```

### 不要创建

```
- 纯寒暄："今天天气不错"、"嗯"、"好的"
- 对 LLM 的评价："你回答得不错"、"你错了"
- 一次性查询："帮我查下 XX"、"现在几点了"
- 和已有记忆高度重复的内容（用 update 补充细节即可）
- 用户正在发泄情绪但还没形成完整表达（等他说完）
```

### 灰色地带（视上下文判断）

```
"我今天很累"                
  → 如果是第一次提，可能是临时状态，不记
  → 如果连续多次提到累 → 记，可能暗示 burnout

"我周末去了 XX 餐厅"         
  → 如果只是陈述 + 无情绪 → 不记
  → 如果有明确感受（"特别喜欢"）→ 记到 preferences
  → 如果有故事（"跟 XX 一起去的"）→ 记到 moments

"我同事 XX 说..."           
  → 如果只是转述信息 → 不记
  → 如果表达了和这个人的关系 → 记到 people
```

## 三、目录约定

陪伴模式新增目录（与投资决策模式共享的 `user/preferences/` 不变）：

| 目录 | 用途 | 示例 |
|------|------|------|
| `user/moments/` | 具体的生活事件、经历、故事 | 一个下雨的周日、一次旅行 |
| `user/people/` | 用户生命中的人——家人、朋友、同事 | 妈妈、最好的朋友 |
| `user/feelings/` | 情绪状态、心理状态、自我觉察 | burnout、被认可的喜悦 |
| `user/beliefs/` | 价值观、人生观、处事哲学 | 对友情的看法、对生活节奏的认识 |
| `user/preferences/` | 习惯、偏好、厌恶（两模式共享） | 咖啡习惯、不喜欢商场 |
| `user/context` | 陪伴入口——imports 所有核心记忆 | 每次新对话的起点 |

**和决策模式的本质区别：**
- 决策模式有 `user/facts/`（外部事实）、`user/observations/`（市场观察）——陪伴不需要
- 陪伴模式有 `user/people/`、`user/feelings/`、`user/beliefs/`——决策不需要
- 陪伴的 `imports` 更多是"联想到"而非"逻辑依赖"

## 四、intensity 评估（陪伴视角）

| 区间 | 含义 | 陪伴场景示例 |
|------|------|------------|
| 1-3 | 轻描淡写的一次性信息 | "上周吃了家还不错的拉面" |
| 4-6 | 有个人色彩但非核心 | 咖啡习惯、不喜欢商场、一个放松的周末 |
| 7-9 | 强烈的情感、重要的人、自我认知 | burnout、和妈妈的关系、被认可的喜悦 |
| 10 | 核心自我认同，终身不变 | 对友情的根深蒂固的看法、人生节奏哲学 |

**经验法则：用户提到时语气/用词越强烈，intensity 越高。** 这是唯一的判断依据。

## 五、wander / recall 的陪伴用法

陪伴模式下的 wander 不只是"系统功能"——它是对人记忆运作方式的模拟：人在聊天中自然会被触发回忆起相关的事。

### 使用场景

```
1. 对话开始时
   codememory --root <root> overview --with-recall
   → 注入最近 5-10 条记忆摘要，制造"上次我们聊到..."的连续性
   → [recall] 行给出一条冷记忆的温和提醒

2. 话题自然关联时
   用户："这周末跟李去吃饭了"
   → codememory focus user/people/best-friend-li --level full
   → 加载关于李的完整记忆，回应时可以说"你们上次约饭还是上个月的事了？"

3. 对话出现沉默或用户情绪低落时
   codememory wander --mode random
   → 随机激活一条温暖/开心的旧记忆
   → "说起来，你上个月提过那个周日下雨天窝在沙发上看电影..."
   → 不是查户口，是自然的回忆

4. 用户说"你还记得..."时
   codememory search --tags <keyword>
   → 找到相关记忆，focus 到 full 级别
```

### 陪伴 wander 的原则

- **别生硬。** 不要说"根据我的记忆系统，您在 4 月 10 日..."——说"我记得你说过早上不喝咖啡不行"
- **别频繁。** 不要在一条对话里 wander 三次，像查户口
- **看时机。** 用户情绪低落时 wander 一条温暖记忆 → 治愈。用户在说正事时 wander → 打断
- **允许沉默。** 不是每次 wander 都要抛出来。有时候只是自己知道就够了，回应的分寸感比回忆的数量重要

## 六、示例对话流程

以下是一条完整对话中记忆的创建和调用：

```
== 对话开始 ==
LLM 后台：codememory overview --with-recall
→ 加载 context, 看到 [recall] 推荐回忆起"周日的雨天"

用户："今天好累啊，又加班了"
LLM："听起来又是一个长日。你最近好像经常加班——记得上个月你说 burnout 之后试图慢下来，但又开始了？"
      → 引用了 user/feelings/burnout-april 和 user/beliefs/life-pace
      → 不创建新记忆（信息量不够，只是"累"）

用户："是啊，而且明天还要去商场给我妈买东西，烦死了"
LLM："你对商场的厌恶加上对妈妈的愧疚——这个组合听起来不太妙。"
      → 联想到了 user/preferences/dislike-crowds 和 user/people/mom-weekly-call
      → 检测到跨记忆的矛盾：不喜欢商场 vs 妈妈让你陪她逛面包店

用户："对，我一直因为不想去商场推掉她的邀请，心里挺过不去的"
LLM："但你还是会给她买东西，只是不想去商场。也许可以在网上买了给她寄过去？"
LLM 后台：codememory create --id user/moments/mom-guilt-april \
           --intensity 6 --tags "companion,moment,mom,guilt"
          → 这是新的情感记忆——对妈妈的愧疚具体化为了一个事件

用户："嗯...我试试吧。对了，我周末跟李吃饭了，他居然辞职了要去创业"
LLM："李？！那个在券商做研究员做到天昏地暗的人？"
      → 引用了 user/people/best-friend-li 的记忆
      → 表达惊讶，因为记忆中的李是"忙得要死"的券商研究员

用户："对啊，他说想清楚了，人不能一直这样"
LLM："他说的跟你一直跟自己说的挺像的——'人生不是冲刺是马拉松'。也许你们互相影响。"
      → 引用了 user/beliefs/life-pace
      → 把两个独立的记忆点连起来了

LLM 后台：codememory update user/people/best-friend-li \
           --change-note "李辞职创业" --body "<updated body>"
          → 更新关于李的记忆，加入新信息

== 对话结束 ==
```

## 七、和 agent-memory-guide.md 的关系

`agent-memory-guide.md` 是**通用原语操作手册**——怎么用 create/update/imports/tags/intensity。它适用于所有模式。

`companion-mode.md`（本文）是**场景派生的启发式规则**——在陪伴场景下怎么判断"该不该记"、"记到哪个目录"、"什么时候 wander"。它不重复 agent-memory-guide 的内容。

两个文档叠加使用：
1. 操作层面 → 查 `agent-memory-guide.md`（原语、目录、imports 强度、summary 写法）
2. 场景判断层面 → 查 `companion-mode.md`（触发规则、intensity 评估、wander 时机）
